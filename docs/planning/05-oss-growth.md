## Context / Why

inconsistent (4 vs 6 vs 3 repos across README.md:18/78/98 and METRICS.md:118 — D600 §1), the
published fastapi recall figure is a known-bad 0% "under investigation", METRICS.md still shows
pre-[1.1.3] zeros, the Discord channel isn't linked from README (D600 §4), and the
contribution funnel has no good-first-issue on-ramp despite this audit generating a ready list
of starter tasks (D600 §3).

## Scope

**In:** benchmark re-run + METRICS/README reconciliation and expansion; fastapi-recall
root-cause; contribution funnel (good-first-issue set, CONTRIBUTING pointer fixes); registry
verification (mcp-name/glama/server.json/openai_tools regenerated); Discord link; insights
showcase in README.
**Out:** paid marketing, docs-site build-out, conference-style content; any feature work.

## Acceptance criteria (epic)

1. `cognirepo benchmark --json` re-run at ≥ 2.2.0 on ≥ 6 repos (flask, fastapi, celery,
   ansible, moby, kubernetes — plus the local `easy`/`medium`/`advanced` fixtures as a cheap
   regression tier); METRICS.md tables replaced with the new run, dated; README repo counts all
   agree with METRICS.md.
2. fastapi memory recall is either fixed with root cause noted, or the row carries an honest
   explanation — no unexplained 0% remains.
3. ≥ 8 issues opened and labeled `good first issue`, each pointing at a Discovery-grounded task;
   CONTRIBUTING.md links the label and DEVELOPER_GUIDE recipes.
4. glama.json / server.json / openai_tools.json verified generated-and-current at the shipped
   version; README mcp-name marker intact.
5. README links Discord and (once EPIC-300 ships) shows the insights report as a screenshot +
   one-paragraph showcase.
